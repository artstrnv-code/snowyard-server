# Snowyard Relay Server 0.3.3 — Staged Roster / Recovery Guards

Основа: Relay Server 0.3.2c. Только Go-сервер, без изменений Java-клиента, физики и Apps Script.

## Добавлено

- Отдельный **opt-in `rosterVersion=2`**: старые клиенты v0/v1 продолжают работать по прежнему протоколу.
- **Изоляция голосования:** уже активные участники подтверждают границу состояния отдельно от нового игрока.
- **Подтверждение вступающего:** `roster_checkpoint` → `roster_join_ready` → `roster_commit`.
- **Очередь одновременных вступлений:** в рамках одной транзакции подтверждается один вступающий, остальные ожидают следующую.
- **Закреплённая контрольная точка:** если Relay располагает согласованным `tick/hash`, он предлагает их в `roster_prepare` и отвергает голос с другим тиком/хешем.
- **Тайм-аут 20 с:** непройденный барьер завершается `roster_aborted`, без выдачи неподтверждённого `roster_commit`.
- **Выход ACTIVE:** требует отдельного подтверждения обновлённого состава, даже если никто не входит.
- **Hash votes:** в v2 считаются только по подтверждённому активному roster; прежние голоса очищаются при смене поколения.
- **Защита recovery:** после повторного расхождения v2 не позволяет координатору снять паузу одним сообщением `coordinator_resume`. Для снятия требуется `recovery_ready` от каждого участника активного roster с текущим snapshotId и заданными tick/hash.
- `/health` сообщает `serverVersion: "0.3.3"`.

## Не изменено

- Формат игровых `command`, `command_batch`, бинарных snapshot, Apps Script, прокси и WebSocket.
- Старые rosterVersion 0/1, включая существующие ограничения v1.
- Go по-прежнему не моделирует игровой мир.

## Проверка

- `go test ./... -count=1` — PASS.
- `go test -race ./... -count=1` — PASS.
- `go vet ./...` — PASS.
- `go build ./...` — PASS.
- Дополнительные тесты: staged P2/P3 join, wrong voter/tick/hash, stored checkpoint, departure commit, forbidden coordinator_resume, unanimous recovery, mixed roster protocol.

## Важные ограничения

Это **серверная основа нового протокола, а не устранение всех P0 на действующем клиенте**. Java 0.12g продолжит работать по v1, пока не будет обновлена. Полностью автоматический recovery при конфликте миров, привязка сохранённого снимка к подтверждённой игровой контрольной точке и масштабирование доставки для 32+ игроков ещё не закончены. Реальные тесты на Render не выполнялись.

# Snowyard Relay Server 0.3.4 — Fresh Frozen Roster Checkpoint

База: Go Relay 0.3.3. Совместимый Java-клиент: Snowyard 0.12i.

## Исправлено

- Удалено требование подтверждать **устаревший** `confirmedTick/confirmedHash` при вступлении игрока. Relay не должен требовать отката мира при отсутствии истории состояний у клиента.
- ACTIVE-клиенты замораживаются и подтверждают **текущий** тик и хеш. Только после единогласного согласования Relay запрашивает у активного координатора **свежий** бинарный снимок именно этого тика.
- Выбранный JOINER повторно загружает свежий снимок через прежний проверенный SHA-256/chunk transport; только после успешного `sync_finish` получает `roster_checkpoint`.
- JOINER больше не может подтвердить устаревший preliminary snapshot. `roster_join_ready` блокируется до завершения fresh snapshot.
- Из журнала при замене свежим замороженным снимком отбрасываются команды прежнего поколения, отправленные за границей заморозки: они не должны применяться к новому составу.
- Для транзакции вступления разрешён снимок на тике 0 (раннее подключение P2).
- Тайм-аут полной транзакции изменён с 20 до 120 секунд, поскольку она теперь включает WebSocket upload/download снимка. Он не заменяет исправление причины зависания.
- Сохранены очередь вступлений, барьер выхода, контроль голосов и совместимость `rosterVersion=1`.
- `/health` сообщает `serverVersion: 0.3.4`.

## Протокол

`roster_prepare` (только ACTIVE) → `roster_ready` (все ACTIVE, current tick/hash) →
`snapshot_requested` (ACTIVE coordinator, указан `generation`/`tick`) →
`snapshot_begin/chunk/commit` → `snapshot_manifest` JOINER →
`snapshot_get`, `sync_poll`, `sync_finish` → `roster_checkpoint` JOINER →
`roster_join_ready` → `roster_commit`.

Если нет JOINER (например, вышел ACTIVE), дополнительный снимок не требуется.

## Ограничения

- Go не может самостоятельно доказать, что SHA-256 байтов снимка соответствует игровому fingerprint: это разные хеши. Используется голосование активных игроков и заявленный тик снимка.
- При настоящем расхождении ACTIVE-клиентов автоматическое восстановление физики ещё не реализовано; сервер не делает ложный commit.
- Требуется Java 0.12i; клиент 0.12h не отвечает на запрос свежего снимка на нулевом тике.
- Интеграционное испытание на Windows/Render отсутствует; нагрузка 32+ игроков не проверена.
